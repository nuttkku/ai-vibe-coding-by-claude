# ⚡ ใช้ Claude Code ให้คุ้มโควต้า (แผน Pro)

ตลอด 5 วันผู้เรียนจะใช้ Claude Code หนักมาก แผน Pro มี **ขีดจำกัดการใช้งาน (usage limits)** ที่รีเซ็ตเป็นรอบเวลา ใช้หมดแล้วต้องรอรอบถัดไป
รายละเอียดเงื่อนไขเปลี่ยนได้ ดูข้อมูลล่าสุดที่ศูนย์ช่วยเหลือของ Anthropic (ลิงก์ใน [CREDITS.md](../CREDITS.md))

> 💡 **หลักคิด:** โควต้าถูกใช้ตาม **ปริมาณบริบท (context)** ที่ Claude ต้องอ่านในแต่ละรอบ ไม่ใช่ตามจำนวนข้อความ
> บทสนทนายาวที่ลากมาทั้งวัน = ทุกข้อความใหม่ต้องแบกประวัติทั้งหมด = เปลืองมาก

## ⌨️ 1. คำสั่งที่ต้องรู้

พิมพ์ `/` ในช่อง Claude Code เพื่อดูคำสั่งทั้งหมดที่มีในเวอร์ชันของคุณ — รายการเต็มดูที่ [Claude Code Cheat Sheet](claude-code-commands.md)

| คำสั่ง / ปุ่ม | ใช้เมื่อ |
|---|---|
| `/clear` | **เริ่มงานใหม่** — ล้างบทสนทนา (CLAUDE.md ยังถูกอ่านเหมือนเดิม) ใช้บ่อยที่สุด |
| `/compact` | บทสนทนายาวแต่ยังทำงานเดิมอยู่ — ให้ Claude สรุปประวัติเหลือเฉพาะที่สำคัญ |
| `/context` | ดูว่าบริบทตอนนี้ใช้ไปเท่าไหร่ และอะไรกินพื้นที่ |
| `/usage` | ดูโควต้าที่ใช้ไปในรอบนี้ (ถ้าเวอร์ชันของคุณมี) |
| `/model` | เลือกรุ่นโมเดล — งานทั่วไปใช้รุ่นมาตรฐาน เก็บรุ่นใหญ่ไว้สำหรับงานยาก |
| **Plan mode** (`Shift+Tab` สลับโหมด) | ให้ Claude วางแผนก่อนลงมือ — ประหยัดกว่าการแก้โค้ดผิดทางแล้วต้องทำใหม่ |
| `Esc` | หยุด Claude ทันทีเมื่อเห็นว่ากำลังไปผิดทาง อย่ารอให้ทำจนเสร็จ |
| `Esc` `Esc` / `/rewind` | ย้อนบทสนทนา (และไฟล์) กลับไปจุดก่อนหน้า |

## 🌱 2. นิสัยที่ประหยัดโควต้า

| ✅ ทำ | ❌ เลี่ยง |
|---|---|
| **1 งาน = 1 บทสนทนา** — จบ task แล้ว commit แล้ว `/clear` | คุยต่อเนื่องทั้งวันในบทสนทนาเดียว |
| อ้างไฟล์ตรงๆ ด้วย `@backend/src/routes/bookings.js` | "ลองหาดูว่าโค้ดจองอยู่ไหน" (Claude ต้องค้นทั้งโปรเจกต์) |
| วาง log เฉพาะส่วนที่ error: `docker compose logs backend --tail 50` | วาง log ทั้งไฟล์หลายพันบรรทัด |
| `CLAUDE.md` สั้น กระชับ เป็นข้อๆ | `CLAUDE.md` ยาวหลายหน้า (ถูกอ่านทุกรอบ) |
| บอกเกณฑ์เสร็จชัดเจน ("รัน test ให้ผ่านแล้วหยุด") | ปล่อยให้ Claude "ปรับปรุงไปเรื่อยๆ" |
| ใช้ Plan mode กับงานใหญ่ ตรวจแผนก่อน | สั่งงานใหญ่ทันที แล้วต้องรื้อทำใหม่ |
| ทำงานง่ายเอง: rename, แก้ typo, `git commit` | ให้ Claude ทำทุกอย่างแม้แต่งาน 5 วินาที |
| ใส่ `node_modules/`, `dist/`, ไฟล์ report ใน `.gitignore` | ให้ Claude อ่านโฟลเดอร์ build/ไฟล์ขนาดใหญ่ |

## 📅 3. จัดสรรโควต้าตามวัน

| วัน | ช่วงใช้ AI หนัก | ช่วงทำเองได้ (ไม่ใช้โควต้า) |
|---|---|---|
| 1 | ลองสั่งงานครั้งแรก (สั้น) | แนะนำตัว, ติดตั้งเครื่องมือ |
| 2 | Bootcamp (ลองคำสั่ง), App Idea, **Scaffold** | Git Bootcamp, Docker Desktop |
| 3 | **UI + test + แก้ตามผลสแกน + CI** (หนักที่สุด) | ทดสอบด้วยมือ, อ่าน report, ตั้ง secrets |
| 4 | **Sprint**, deploy script | สร้าง VM, รอ Nessus, Deploy ตามขั้นตอน, ซ้อม Demo |
| 5 | — (Demo Day) | นำเสนอ |

**เคล็ดลับวันหนัก (2–4):** เริ่มเช้าด้วย `/clear` และแผนงานใน Plan mode, commit ทุก task, `/clear` ทุกครั้งที่เปลี่ยน task

## 🆘 4. เมื่อชนขีดจำกัด (Plan B)

1. **อย่าตกใจ** — ดูว่ารีเซ็ตเมื่อไหร่ (Claude Code จะแจ้ง) แล้วทำงานที่ไม่ต้องใช้ AI ระหว่างรอ:
   - review `git diff` และเขียน commit message เอง
   - ทดสอบแอปด้วยมือ, จดบั๊กพร้อมขั้นตอน reproduce ไว้เป็น Prompt ชุดถัดไป
   - รัน Snyk / ZAP / Nessus และอ่านผล
   - ทำสไลด์ Demo ([templates/demo-presentation.md](../templates/demo-presentation.md))
2. **จับคู่ (Pair)** — ทำงานบนเครื่องเพื่อนที่ยังมีโควต้า โดยสลับกันเป็นคนพิมพ์ Prompt
3. **เตรียม Prompt ไว้ล่วงหน้า** — เขียน Prompt ที่ชัดเจนพร้อมบริบทไว้ในไฟล์ เมื่อโควต้ากลับมาจะได้ใช้คุ้มทุกข้อความ
4. **วิทยากร:** ใช้ checkpoint หรือโค้ดตัวอย่างช่วยให้ผู้เรียนตามทันแทนการใช้โควต้าซ้ำ

## 🚦 5. สัญญาณว่าบทสนทนาควร `/clear` แล้ว

- Claude เริ่มลืมกฎใน `CLAUDE.md` หรือแก้สิ่งที่เคยแก้ไปแล้วซ้ำ
- วนแก้บั๊กเดิมเกิน 3 รอบ → `/clear` แล้วเริ่มใหม่ด้วย Prompt ที่สรุปปัญหาให้ชัด (มักได้ผลดีกว่า)
- `/context` แสดงว่าบริบทใกล้เต็ม
- เปลี่ยนไปทำงานคนละส่วนของแอป
