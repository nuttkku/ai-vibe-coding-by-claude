# 🎤 วันที่ 5 — Demo Day: นำเสนอผลงาน Vibe Coding

**วันนี้ไม่มีการสอน** — ผู้อบรมทุกคนขึ้นนำเสนอแอปที่สร้างด้วย Claude Code ตลอด 4 วันที่ผ่านมา บน URL จริง พร้อมแชร์ Prompt/Strategy และสิ่งที่เรียนรู้

## 🎯 เป้าหมายของวัน

- 🎬 ทุกคนนำเสนอ Live Demo บน URL จริง
- 💬 แชร์ Prompt/Strategy ที่ได้ผล ให้เพื่อนร่วมรุ่นได้เรียนรู้จากกันและกัน
- 🪞 สะท้อนคิดว่า Vibe Coding ได้ผลตรงไหน และต้องระวังอะไร

## ⏰ ตารางเวลา (แนะนำ)

| เวลา | กิจกรรม |
|---|---|
| 08:30–09:00 | 🔌 เปิด VM + เช็ก URL (Quick Tunnel อาจได้ URL ใหม่) + ต่อจอทดสอบ |
| 09:00–12:00 | 🎬 นำเสนอรอบเช้า (คนละ ~10 นาที รวมถาม-ตอบ) |
| 13:00–15:00 | 🎬 นำเสนอรอบบ่าย |
| 15:00–15:40 | 🤝 แชร์ Prompt/Strategy + อภิปรายสิ่งที่เรียนรู้ |
| 15:40–16:00 | 🎓 ปิดหลักสูตร + แบบประเมิน |

> 💡 จำนวนคนต่อรอบขึ้นกับขนาดรุ่น — 10 นาที/คน นำเสนอได้ประมาณ 30 คนในหนึ่งวัน ถ้าคนเยอะกว่านี้ให้ลดเหลือ 7 นาที

## 🔌 ก่อนเริ่ม (08:30)

- เปิด VM → `docker compose -f docker-compose.prod.yml ps` ต้องขึ้นครบ
- ดู URL ล่าสุด: `docker compose -f docker-compose.prod.yml logs tunnel-quick | grep trycloudflare.com` แล้วแก้ในสไลด์
- เปิดเว็บจากมือถือ (4G) ไล่ flow ที่จะ Demo อีกรอบ
- 🆘 **แผนสำรอง:** ถ้า URL ใช้ไม่ได้ ให้ Demo จาก `docker compose up` ในเครื่องตัวเอง + ภาพหน้าจอ URL ที่เคยใช้ได้เมื่อวาน

## 🤝 2. แชร์ Prompt/Strategy + สิ่งที่เรียนรู้

ให้ผู้เรียนแต่ละคนเพิ่ม Prompt ที่ได้ผลที่สุด 1–3 อันลงใน [`prompts/`](../prompts/) ผ่าน Pull Request (ถ้าต้องการแบ่งปันกับรุ่นต่อไป)

คำถามสะท้อนคิด:
- ตอนไหนที่ "vibe" ได้ผลดีที่สุด? ตอนไหนต้องหยุดอ่านโค้ดเอง?
- ถ้าเริ่มใหม่ จะเขียน `CLAUDE.md` ต่างไปอย่างไร?
- Security finding ที่ทำให้ประหลาดใจที่สุดคืออะไร?
